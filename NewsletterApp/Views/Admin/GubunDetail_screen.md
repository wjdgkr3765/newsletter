# GubunDetail_screen.md

화면 설계 문서다. 원본 템플릿은 `docs/screen.md`다. 화면을 바꾸는 작업에서는 이 문서도 함께 갱신한다.

---

## 1. 기본 정보

- **화면 파일 경로**: 프로젝트/NewsletterApp/Views/Admin/GubunDetail.cshtml
- **화면 이름**: 발송 설정 상세
- **화면 목적**: 종류 하나의 발송 시간과 사용 여부를 고치고, 오늘 뉴스레터를 직접 만들어 보내거나 받지 않은 구독자에게 다시 보낸다.
- **접근 URL**: /admin/gubuns/{id}
- **접근 권한**: 관리자. 로그인 안 했으면 `/login`, 일반 사용자는 `/newsletters`, 종류가 없으면 `/admin/gubuns`로 이동
- **시안 파일 경로**: 프로젝트/docs/mockups/gubun_detail.html

### 시안 작성 규칙
- 파일명은 화면 파일명을 snake_case로 쓴다. (예: `Register.cshtml` → `register.html`)
- 프로젝트의 부트스트랩을 상대 경로로 불러와 실제 화면과 같은 스타일로 만든다. 서버 없이 파일을 바로 열어 볼 수 있어야 한다.
- 기능 없이 화면 모양과 "6. 상태별 화면"의 상태만 보여준다.
- 설계가 바뀌면 시안도 함께 고친다.
- 이 화면 시안은 "오늘 뉴스레터 없음"과 "오늘 뉴스레터 있음"을 둘 다 보여준다.

## 4. 동작

| 요소 | 사용자 동작 | 결과 |
|---|---|---|
| 화면 | 열림 | `GET /api/admin/gubuns/{id}`, `GET /api/admin/gubuns/{id}/today` |
| 발송 시간, 사용 여부 | 변경 | 화면 값만 바뀐다(스위치 라벨 "사용"/"사용 안 함"). 저장하지 않는다 |
| 저장 버튼 | 클릭 | `POST /api/admin/gubuns/{id}/config` → 성공하면 "저장했습니다.", 설정 없음 안내 숨김 |
| 지금 만들어 보내기 | 클릭 | 확인 팝업 |
| 다시 보내기 | 클릭 | 확인 팝업 |
| 확인 팝업 취소 | 클릭 | 팝업 닫기 |
| 확인 팝업 보내기 | 클릭 | 팝업 닫고 두 발송 버튼 비활성화, 보내는 중 표시 → `POST .../today/send` 또는 `POST .../today/resend` → 끝나면 결과 문구, `GET .../today`로 오늘 카드 다시 조회. NEWSLETTER_EXISTS, NO_SUBSCRIBER, NO_PENDING_SUBSCRIBER, CONTENT_FETCH_FAILED, SEND_FAILED, SENDING_IN_PROGRESS는 결과 문구에 메시지 |
| 목록 링크 | 클릭 | 뉴스레터 설정 화면(`/admin/gubuns`)으로 이동 |
| 메뉴 항목, 로그아웃 | 클릭 | History_screen.md "4. 동작"의 메뉴 이동과 같음 (수신 내역, 내 구독, 회원 관리, 구독, 뉴스레터 설정, 내 정보, 로그아웃 → `/login`) |
| (공통) | API가 401 응답 | 로그인 화면(`/login`)으로 이동 |

## 5. 데이터

### 사용 API
| 메서드 | 경로 | 용도 |
|---|---|---|
| GET | /api/admin/gubuns/{id} | 종류와 발송 설정 |
| POST | /api/admin/gubuns/{id}/config | 발송 설정 저장 |
| GET | /api/admin/gubuns/{id}/today | 오늘 뉴스레터 상태 |
| POST | /api/admin/gubuns/{id}/today/send | 지금 만들어 보내기 |
| POST | /api/admin/gubuns/{id}/today/resend | 받지 않은 구독자에게 다시 보내기 |
| POST | /api/auth/logout | 로그아웃 (공통 레이아웃) |

### 사용 테이블
- gubuns, newsletter_configs, newsletters, historys, subscriptions, users
