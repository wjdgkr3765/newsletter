# overview.md

프로젝트 개요의 기준 문서다. 설계와 각 단계의 완료 기준은 이 문서를 기준으로 정한다.

기능이나 범위를 바꾸는 작업에서는 이 문서도 함께 갱신한다. 사용자 승인 없이 기능과 범위를 바꾸지 않는다.

비어 있는 항목이 있으면 loop.md 1번(설계)에서 사용자에게 질문해서 채운다.

---

## 1. 기본 정보

- **프로젝트 이름**: 뉴스레터 (NewsletterApp)
- **한 줄 소개**: 뉴스레터 종류(예: 유가 정보, 날씨 정보)별로 구독한 회원에게 매일 정해진 시간에 뉴스레터를 만들어 이메일로 보내는 웹 서비스
- **목적**: 종류별 뉴스레터를 매일 자동으로 만들어 구독자에게 전달한다.

## 2. 사용자와 권한

| 사용자 | 설명 | 할 수 있는 일 |
|---|---|---|
| 비회원 | 로그인하지 않은 사용자 | 회원가입, 로그인, 비밀번호 찾기, 메일의 수신 거부 링크로 수신 거부 |
| 일반 사용자 | 가입한 회원 (`users.is_admin = 0`) | 구독한 종류의 뉴스레터를 메일로 받음. 수신 내역(자신이 받은 것만), 내 구독, 내 정보 화면만 이용 |
| 관리자 | 가입한 뒤 DB에서 관리자로 지정한 회원 (`users.is_admin = 1`) | 모든 화면 이용. 회원 관리, 구독 관리, 뉴스레터 설정, 모든 수신 내역 조회. 구독한 종류 수신, 내 정보 수정. 탈퇴는 불가 |
| 정지 회원 | 관리자가 정지한 회원 (`users.is_suspended = 1`) | 로그인 불가. 구독 관리 화면에 보이지 않고 발송 대상에서 빠짐 |

- 관리자 계정은 화면에서 만들거나 지정하지 않는다. 회원가입한 계정을 DB에서 관리자로 바꾼다. (`UPDATE users SET is_admin = 1 WHERE login_id = '아이디'`)
- 관리자 여부와 정지 상태는 로그인할 때 읽는다. 로그인 중에 정지되거나 관리자 여부가 바뀌면 다음 로그인부터 적용된다.
- 모든 권한은 서버에서 확인한다. 다른 회원의 데이터는 보거나 바꿀 수 없다.

### 기능 상세 규칙

#### 회원가입
- 아이디: 영문 소문자+숫자 6~20자, 중복 불가
- 비밀번호: 8~20자, 영문·숫자·특수문자 각 1자 이상. 비밀번호 확인과 같아야 한다.
- 이메일: 이메일 형식, 최대 50자, 중복 불가. 앞뒤 공백을 빼고 소문자로 바꿔 저장·비교한다.
- 이름: 앞뒤 공백 제외 2~30자
- 입력하는 즉시 검사 결과를 보여준다. (형식은 화면에서, 아이디·이메일 중복은 API로)
- 이메일 인증 코드 확인이 필수다.
- 가입하면 정상 상태의 일반 사용자가 된다.

#### 인증 코드 (회원가입, 비밀번호 찾기, 이메일 변경 공통)
- 6자리 숫자, 보낸 때부터 10분 동안 유효, 5번 틀리면 그 코드는 쓸 수 없다.
- 다시 받으면 이전 코드는 쓸 수 없다.
- 코드를 확인하면 "인증 완료" 상태가 되고, 확인한 때부터 30분 안에 가입·비밀번호 변경·이메일 저장을 마쳐야 한다. 마치면 인증 완료 상태는 없어진다.
- 앱 메모리(IMemoryCache)에 저장하므로 앱을 다시 시작하면 없어진다.

#### 로그인
- 아이디가 틀렸을 때, 비밀번호가 틀렸을 때, 정지 회원일 때 모두 "아이디 또는 비밀번호가 맞지 않습니다."로 똑같이 알린다.
- 같은 아이디(입력한 문자열 기준, 회원 존재 여부와 무관)로 5번 연속 실패하면 10분 동안 로그인을 막고 "로그인 시도가 많아 10분 뒤에 다시 시도해 주세요."를 보여준다. 성공하면 실패 횟수를 지운다. (security.md 2번)
- 로그인하면 수신 내역 화면으로 이동한다. 로그인은 60분 동안 유지되고 사용하는 동안 연장된다.
- 로그인한 사용자가 로그인·회원가입·비밀번호 찾기 화면에 들어오면 수신 내역 화면으로 보낸다.
- 로그인하지 않고 로그인이 필요한 화면에 들어오면 로그인 화면으로 보낸다. 일반 사용자가 관리자 화면에 들어오면 수신 내역 화면으로 보낸다.
- 로그아웃하면 서버의 로그인 세션을 지우고 로그인 화면으로 이동한다.

#### 비밀번호 찾기
- 아이디와 이메일이 같은 회원의 것이 아니거나 정지 회원이면 "아이디와 이메일이 일치하는 회원이 없습니다."로 알리고 메일을 보내지 않는다.
- 새 비밀번호 규칙은 회원가입과 같다. 지금 비밀번호와 같아도 된다. 바꾸면 로그인 화면으로 이동한다. 임시 비밀번호는 보내지 않는다.
- 로그인 화면에 "비밀번호 찾기" 링크를 둔다.

#### 내 정보 수정, 회원 탈퇴
- 화면은 기본 정보, 비밀번호 변경, 회원 탈퇴 세 부분이다.
- 아이디와 가입일은 보기만 한다.
- 이메일을 그대로 두면 인증 없이 이름만 저장한다. 바꾸면 새 이메일 인증이 필요하고, 다른 회원이 쓰는 이메일로는 바꿀 수 없다.
- 비밀번호는 현재 비밀번호를 확인한 뒤 바꾼다. 바꾼 뒤에도 로그인은 유지된다.
- 탈퇴는 확인 팝업에서 현재 비밀번호를 입력한다. 그 회원의 구독, 수신 내역, 회원 정보를 지우고 로그아웃한 뒤 로그인 화면으로 이동한다. 이미 만들어진 뉴스레터는 남는다. 같은 아이디와 이메일로 다시 가입할 수 있다.
- 관리자에게는 탈퇴 버튼 대신 "관리자는 탈퇴할 수 없습니다." 문구를 보여준다. 서버도 거부한다.

#### 회원 관리
- 회원 목록: 아이디, 이름, 권한("관리자"/"일반"), 상태("정상"/"정지"), 가입일. 이름 오름차순(같으면 아이디 오름차순), 10명씩.
- 정지·정지 해제는 확인 팝업을 거친다. 다른 관리자는 정지할 수 있고, 자기 자신은 정지할 수 없다.

#### 구독 관리
- 정지 회원을 뺀 모든 회원(관리자 포함)의 이름과 이메일을 이름 오름차순(같으면 아이디 오름차순), 10명씩.
- 드롭다운: '전체'(기본값)와 뉴스레터 종류들(종류 이름 오름차순). '전체'면 체크박스가 없다. 종류를 고르면 체크박스가 나오고 구독한 회원이 체크되어 있다.
- 체크하면 바로 구독, 풀면 바로 해지. 이미 원하는 상태면 성공으로 처리한다. 실패하면 체크를 되돌리고 오류를 보여준다.

#### 내 구독
- 모든 종류(종류 이름 오름차순): 종류 이름, 발송 시간("매일 HH:mm", 한국 시간), 구독 스위치. 발송 설정이 없거나 사용 안 함이면 "지금은 발송하지 않음".
- 스위치를 켜면 바로 구독, 끄면 바로 해지. 실패하면 되돌리고 오류를 보여준다. 이미 원하는 상태면 성공으로 처리한다.
- 사용 안 함인 종류도 구독할 수 있다. 나중에 사용으로 바뀌면 받는다. 자기 구독만 바꿀 수 있다.

#### 뉴스레터 설정
- 종류 목록: 종류 이름, 발송 시간(한국 시간), 사용 여부("사용"/"사용 안 함"). 발송 설정이 없는 종류는 발송 시간과 사용 여부 자리에 "설정 없음". 정렬은 종류 이름 오름차순. 종류를 누르면 발송 설정 상세 화면.
- 종류 추가 팝업(목록 화면 오른쪽 위 버튼): 종류 이름(앞뒤 공백 제외 1~20자, 중복 불가), 발송 시간(시·분), 사용 여부. 기본값 16:00, 사용 안 함. "추가"를 눌러야 저장되며 종류와 발송 설정이 함께 만들어진다.
- 발송 설정 상세: 시·분 선택 상자(1분 단위), 사용 여부 스위치(켜면 "사용", 끄면 "사용 안 함" 표시). "저장"을 눌러야 저장된다. 설정이 없는 종류는 저장하면 만들어진다(이때 기본값 16:00, 사용 안 함으로 보여준다).
- 종류 하나에 발송 설정은 하나다. 종류 이름 수정과 종류 삭제는 하지 않는다.
- 보내는 사람 이메일은 화면에 보여주지 않는다. `.env`에 넣은 Gmail 주소를 쓴다.

#### 뉴스레터 자동 생성·발송
- 사용 여부가 "사용"인 종류만, 발송 시간(한국 시간 시·분)이 된 그 1분 안에만 보낸다. 그 시간에 프로그램이 꺼져 있었으면 그날은 보내지 않는다. 주말·공휴일 구분 없이 매일.
- 같은 종류는 하루(한국 날짜)에 한 번만. 구독한 정상 회원이 없으면 만들지 않는다.
- 제목: "[종류 이름] YYYY-MM-DD"(한국 날짜). 본문: 그 종류의 본문 생성기가 없으면 종류 이름과 날짜만 들어간 기본 본문.
- 종류별 본문은 외부 데이터를 받아 만든다("날씨 정보(지역)"는 아래 "종류별 본문: 날씨 정보", 다른 종류는 나중에 정한다). 데이터를 받지 못하면 그날 그 종류는 보내지 않는다(기본 본문으로 대신하지 않는다).
- 회원마다 한 통씩 보낸다(수신 거부 링크가 회원마다 다르다). 받는 데 성공한 회원만 수신 내역에 남긴다. 실패는 기록하지 않고 자동으로 다시 보내지 않는다.
- 한 명이라도 받으면 발송된 것으로 본다. 아무도 받지 못해도 그 뉴스레터는 지우지 않고 그대로 둔다(발송되지 않은 것으로 본다). 그날은 오늘 뉴스레터가 있으므로 새로 만들 수 없고, 관리자가 "받지 않은 구독자에게 다시 보내기"로 보낼 수 있다.
- 메일 맨 아래: "더 이상 받지 않으려면 수신 거부를 눌러 주세요." 문구와 "수신 거부" 링크.

#### 종류별 본문: 날씨 정보
- 종류 이름이 "날씨 정보(지역 이름)"인 종류에 쓴다. 예: "날씨 정보(서울)", "날씨 정보(부산)". 관리자가 뉴스레터 설정에서 이 이름으로 종류를 추가하면 적용되고, 회원은 내 구독에서 원하는 지역 종류를 켠다. 괄호 안 지역이 아래 지역 목록에 없으면 기본 본문이다.
- 데이터: 기상청 단기예보 조회서비스(공공데이터포털).
- 지역 목록 (17곳, 기상청 격자 X·Y, `appsettings.json`의 `Weather:Regions`. 좌표는 docs/reference 격자 엑셀 기준)

  | 울릉도 | 127, 127 | 독도 | 144, 123 | | |
- 본문 (제목은 다른 종류와 같은 "[종류 이름] YYYY-MM-DD". 예: "[날씨 정보(서울)] 2026-11-20")
  1. 전국 날씨 지도 이미지 (가로 600px PNG): 한국 지도 위 17곳마다 지역 이름, 오늘 12:00 날씨 아이콘, "최저/최고" 기온(예: "2/11°"). 구독한 지역(그 종류의 지역)은 이름표 테두리를 강조색으로 그린다. 이름표가 서로 겹치지 않도록 지역마다 이름표 위치를 정해 둔다(시안 weather_mail.html 배치). 위쪽에 "오늘 날씨 YYYY-MM-DD". 값을 받지 못한 다른 지역은 아이콘 대신 "-"로 그린다.
  2. "오늘(YYYY-MM-DD) {지역} 날씨"와 "최저 n°C / 최고 n°C"
  3. 시간별 표: 06:00, 09:00, 12:00, 15:00, 18:00, 21:00 여섯 줄. 열은 시간, 날씨, 기온(°C), 강수 확률(%)
  4. 맨 아래(수신 거부 영역 위) 출처 표시(공공누리 제1유형 조건): "이 메일의 날씨 정보는 기상청이 공공누리 제1유형으로 개방한 '기상청_단기예보 조회서비스'를 이용했으며, 공공데이터포털(www.data.go.kr)에서 무료로 받을 수 있습니다." 기상청 로고는 넣지 않고, 기상청이 이 서비스를 보증하는 것처럼 보이는 표현은 쓰지 않는다.
- 날씨 표시: 강수 형태가 있으면 강수 형태(비, 비/눈, 눈, 소나기), 없으면 하늘 상태(맑음, 구름많음, 흐림). 지도 아이콘도 같은 7가지로 구분한다(아이콘은 코드로 그린다).
- 지도 윤곽은 Natural Earth 행정경계 데이터(퍼블릭 도메인)로 그린다. 참고 예시 이미지(방송 화면)는 배치만 참고하고 쓰지 않는다.
- 쓰는 예보: 오늘 02:00 발표. 발송 시각이 02:10(한국 시간) 전이면 전날 23:00 발표를 쓴다. 두 발표 모두 오늘 06:00~21:00 값과 오늘 최저·최고 기온을 담고 있다.
- 그 종류 지역의 필요한 값(여섯 시각의 날씨·기온·강수 확률, 최저·최고 기온) 중 하나라도 없거나, 응답이 오류이거나, 10초 안에 응답이 없거나, 지도 이미지를 만들지 못하면 데이터를 받지 못한 것으로 본다. 그날 그 종류는 보내지 않는다(관리자 직접 발송이면 "본문 데이터를 받지 못해 만들지 않았습니다."). 다른 지역의 값을 받지 못한 것은 실패로 보지 않는다(지도에 "-").
- 같은 발표의 같은 지역 예보는 앱 메모리에 1시간 동안 보관해 다시 쓴다(지역 종류 여러 개가 같은 때 보낼 때 API를 다시 부르지 않기 위해).
- 수신 내역 본문 팝업에도 지도 이미지와 표가 보인다.

#### 관리자 직접 발송, 다시 보내기
- 발송 설정 상세 화면 아래 "오늘 뉴스레터" 영역.
- 오늘(한국 날짜) 그 종류의 뉴스레터가 없으면 "지금 만들어 보내기": 사용 여부·발송 시간과 관계없이 지금 만들어 구독한 정상 회원에게 보낸다. 구독자가 없으면 만들지 않는다. 직접 보낸 날은 자동 발송하지 않는다.
- 오늘 뉴스레터가 있으면 "받은 회원 n명 / 받지 않은 구독자 m명"과 "받지 않은 구독자에게 다시 보내기". 받지 않은 구독자 = 지금 그 종류를 구독한 정상 회원 중 이 뉴스레터를 받은 기록이 없는 회원(보낸 뒤 새로 구독한 회원 포함).
- 메일 내용과 수신 거부 링크는 자동 발송과 같다. 지난 날짜 뉴스레터는 다시 보내지 않는다.
- 버튼을 누르면 확인 팝업을 띄우고, 보내는 동안에는 버튼을 누를 수 없다. 같은 종류의 발송이 이미 진행 중이면 서버가 거부한다.

#### 뉴스레터 수신 내역
- 발송된 뉴스레터(받은 회원이 1명 이상)를 최근 발송 순으로 30개씩. 제목, 종류, 발송 시각(한국 시간 "YYYY-MM-DD HH:mm"). 아무도 받지 못한 뉴스레터는 관리자 목록에도 보이지 않는다.
- 누르면 팝업으로 본문을 보여준다. 팝업 본문에는 수신 거부 링크가 없다.
- 일반 사용자는 자신이 받은 뉴스레터만 보고, 다른 사람이 받은 뉴스레터의 본문은 볼 수 없다.
- 관리자는 직접 받았는지와 관계없이 모든 뉴스레터를 보고, 관리자 목록에만 "구독자" 열(그 뉴스레터를 받은 회원 수)이 있다.

#### 메일 수신 거부
- 링크는 회원·종류마다 다르고 위조할 수 없다(ASP.NET Core Data Protection). 만료는 없다(예전 메일의 링크도 쓸 수 있다).
- 링크를 열면 로그인 없이 종류 이름이 있는 확인 화면이 나온다. "수신 거부" 버튼을 눌러야 해지된다. 이미 해지된 상태면 성공으로 처리한다.
- 링크가 올바르지 않거나 그 회원·종류가 없어졌으면 "링크가 올바르지 않거나 더 이상 쓸 수 없습니다."
- 다시 받으려면 로그인한 뒤 "내 구독"에서 켠다.

## 7. 제약 사항

- **지원 브라우저**: Chrome 최신 버전 (데스크톱)
- **실행 환경**: 로컬 PC에서만 실행한다. 서버 배포는 하지 않는다.
- **시각**: 시각(순간)은 UTC로 저장하고 화면에는 한국 시간으로 보여준다. "하루"는 한국 날짜 기준이다. 발송 시간(`send_time`)은 순간이 아니라 매일 반복되는 시·분이므로 한국 시간 그대로 저장한다.
- **메일**: Gmail 계정 하나로 SMTP 발송한다. Gmail의 하루 발송 한도(일반 계정 약 500통)를 넘으면 실패한다.
- **앱 메모리**: 인증 코드, 로그인 실패 횟수, 로그인 세션은 앱 메모리에 있으므로 앱을 다시 시작하면 없어진다(로그인한 회원은 다시 로그인해야 한다).
- **날씨 API**: 공공데이터포털에서 "기상청_단기예보 조회서비스"를 활용 신청해 받은 인증키가 필요하다. 인증키가 없거나 틀리면 "날씨 정보(지역)" 종류는 보내지 않는다.
- **날씨 지도**: 지도 글자는 Windows 기본 글꼴 "맑은 고딕"으로 그린다(Windows PC에서만 실행). 지도 이미지는 본문(`newsletters.content`)에 함께 저장되므로 날씨 뉴스레터 하나가 약 150KB 이하가 되도록 만든다(SQL Server Express는 DB 하나에 10GB까지).
- **수신 거부 링크**: Data Protection 키는 기본 위치(`%LOCALAPPDATA%\ASP.NET\DataProtection-Keys`)에 보관된다. 이 폴더를 지우면 예전 메일의 수신 거부 링크를 쓸 수 없다.
