# decision.md

사용자가 내린 결정과 그 이유를 기록하는 문서다. 세션이 바뀌어도 같은 질문을 반복하지 않기 위해 쓴다.

## 운영 규칙
- 질문에 대한 사용자의 답, 사용자가 선택한 방법은 결정 즉시 기록한다.
- 질문하기 전에 이 문서를 확인한다. 이미 결정된 내용은 다시 묻지 않는다.
- 사용자의 요청이 기존 결정과 다르면, 기존 결정을 알리고 바꿀지 확인한다.
- 결정은 지우지 않는다. 결정이 바뀌면 기존 항목의 상태를 "변경됨"으로 바꾸고 새 항목을 추가한다.
- 결정 때문에 다른 문서(overview.md, spec.md 등)를 바꿔야 하면 그 문서도 함께 갱신한다.

### D-005 아무도 받지 못한 뉴스레터 처리
- 날짜: 2026-11-12
- 질문/상황: 설계 검토에서, 뉴스레터를 만들었지만 모든 회원에게 발송이 실패했을 때 그 뉴스레터를 지울지 물음 (설계 초안은 지우는 것이었음)
- 결정: 지우지 않고 그대로 둔다. 그날은 하루 한 번 규칙에 따라 새로 만들지 않고, 관리자가 "받지 않은 구독자에게 다시 보내기"로 보낼 수 있다. 받은 회원이 없으므로 발송된 것으로 보지 않아 수신 내역 목록(관리자 포함)에는 보이지 않는다.
- 이유: 사용자 결정
- 관련 문서/파일: docs/overview.md 3번, docs/database.md 삭제 규칙, docs/api.md 6.3·6.8·7번
- 상태: 유효

### D-006 비밀 정보 관리: User Secrets 대신 .env
- 날짜: 2026-11-12
- 질문/상황: 구현 전 비밀 정보(DB 접속 문자열, Gmail 주소, Gmail 앱 비밀번호) 넣는 방법 안내 중, 사용자가 .env 방식으로 하라고 함 (D-002는 User Secrets)
- 결정: `NewsletterApp/.env`에 넣고 DotNetEnv로 읽어 환경 변수로 등록한다. 변수 이름은 `ConnectionStrings__Default`, `Gmail__Address`, `Gmail__AppPassword`. `.env`는 git에서 제외하고, 값을 비운 `.env.example`을 커밋한다. 값은 사용자가 직접 넣는다.
- 이유: 사용자 결정
- 관련 문서/파일: docs/spec.md, docs/structure.md, docs/overview.md, docs/api.md 7번
- 상태: 유효
